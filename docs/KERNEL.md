# 内核通用化（Phase 1）

这一层不再把“工程 JSON → 接口 → 表 → MySQL → Node 运行时”串成一条硬链，而是拆成四段可替换的内核：

```
工程 / 数据库 / 外部 DSL
        ↓  adapter
   元模型 registry        实体 · 字段 · 关联 · 枚举 · 校验规则
        ↓
   方言层 dialect          MySQL / PostgreSQL / SQLite
        ↓
   迁移器 migration        init / diff / ALTER / 回滚 / checksum
        ↓
   渲染器 renderer         Go / Rust / Node / Java（后续接入）
```

元模型和方言都不认识 ClickBuild 的 `interfaces`、`routes`、`.yxpp`。工程适配器只负责把现有结构翻译进来。

## 元模型

核心结构：

```json
{
  "version": 1,
  "entities": [
    {
      "id": "iface:table",
      "name": "users",
      "primaryKey": "id",
      "fields": [
        { "name": "id", "type": "bigint", "primaryKey": true, "autoIncrement": true },
        { "name": "email", "type": "varchar", "length": 320, "nullable": false, "unique": true },
        { "name": "status", "type": "varchar", "enumRef": "user_status" }
      ],
      "indexes": [{ "name": "idx_users_status", "columns": ["status"] }],
      "relations": [
        { "name": "user_posts", "kind": "one-to-many", "target": "posts", "foreignKey": "user_id" },
        { "name": "post_author", "kind": "many-to-one", "target": "users", "field": "user_id" }
      ]
    }
  ],
  "enums": [{ "name": "user_status", "values": ["active", "disabled"] }],
  "rules": [{ "entity": "users", "field": "email", "kind": "pattern", "value": "^[^@]+@[^@]+$" }]
}
```

逻辑类型固定为：`bigint / int / smallint / tinyint / bool / decimal / float / double / varchar / char / text / longtext / datetime / date / time / json`，以及语义类型 `token / url / file / image / video / audio / pdf / doc / excel / archive`。

关联只描述关系，不强制生成外键约束。`many-to-many` 通过 `through` 指向中间实体；中间表仍然是一个普通实体。

校验规则（`rules.kind`）：`required / nullable / minLength / maxLength / pattern / min / max / unique / enum / custom`。目前是元数据 + 校验器，不直接落成数据库约束。

## 方言

```js
const { dialectOf } = require('./app/kernel/dialects');
const d = dialectOf('postgres'); // mysql | postgres | sqlite
d.createTable(entity);           // 返回语句数组（含 PG 注释）
d.addColumn(entity, field);
d.alterColumn(oldEntity, newEntity, oldField, newField);
```

差异点：

- MySQL：反引号、`AUTO_INCREMENT`、`ENGINE=InnoDB`、列 `COMMENT`、`ON UPDATE CURRENT_TIMESTAMP`。
- PostgreSQL：双引号、`GENERATED BY DEFAULT AS IDENTITY`、`JSONB`、`COMMENT ON TABLE/COLUMN`。
- SQLite：`INTEGER PRIMARY KEY AUTOINCREMENT`、动态类型、忽略工程里的 MySQL schema 名。
- SQLite 不支持直接改列：任何字段/索引变化合并成一次表重建，先建临时表、复制同名字段、删旧表、改名、重建索引。

## 迁移

```js
const { initMigration, diffMigration, writeMigration } = require('./app/kernel/migrate');

const m1 = initMigration(registry, 'sqlite', { version: '0001' });
const m2 = diffMigration(oldRegistry, newRegistry, 'sqlite', { version: '0002' });
writeMigration(m2, 'db/migrations');
```

- `initMigration`：按关联拓扑排序建表，再建索引。
- `diffMigration`：按实体 `id` 识别表改名；新增/删除表；新增/删除字段；字段类型、长度、可空、默认值、自增、唯一、注释变化；索引增删改。
- MySQL 用 `ALTER TABLE ... ADD/MODIFY/DROP`；PostgreSQL 用 `ALTER COLUMN TYPE / SET DEFAULT / SET NOT NULL`；SQLite 用表重建。
- 每个迁移带 `version`、`name`、`fromVersion`、`up`、`down`、`warnings`、`checksum`。
- `applySqlite(db, m)` 会建 `schema_migrations` 表、按版本去重、记录 checksum；`rollbackSqlite(db, m)` 执行 DOWN 并删除记录。
- 删除表/字段的 DOWN 只能还原空结构，`warnings` 会明确写“UP 会丢数据”。

## 反向工程

```bash
node tools/kernel-cli.js reverse-mysql --host 127.0.0.1 --port 13306 --user root --database blog --out blog.project.json
node tools/kernel-cli.js reverse-sqlite ./app.sqlite --out app.project.json
```

- MySQL：读 `information_schema.COLUMNS / STATISTICS / KEY_COLUMN_USAGE`，识别主键、自增、枚举、索引、外键（`many-to-one`）。
- SQLite：读 `sqlite_master`、`PRAGMA table_info / index_list / index_info / foreign_key_list`。
- 默认排除 `schema_migrations`；需要时加 `--include-internal`（代码层 `{ includeInternal: true }`）。
- 产出 registry 后，`projectFromRegistry()` 会落成现有 UI 能打开的 `interfaces[].tables`，并补一套默认 CRUD 路由。
- PostgreSQL 反向工程接口已留出，但 reader 尚未接线；方言 DDL 已支持 PostgreSQL。

## CLI

```bash
node tools/kernel-cli.js inspect path/to/project.json
node tools/kernel-cli.js ddl path/to/project.json --dialect postgres
node tools/kernel-cli.js init path/to/project.json ./db/migrations --dialect mysql
node tools/kernel-cli.js diff old.json new.json ./db/migrations --dialect sqlite --version 0002
```

## 已验证

- `node tools/test-kernel.js`：15 项通过。26 套内置案例全部能转成 registry、0 个元模型错误、全部能在 SQLite 初始化。
- `node tools/test-kernel-mysql.js`：真实 MariaDB 上初始化、加字段、改字段、加索引、反向工程通过。
- PostgreSQL 只做了 DDL/ALTER 字符串断言，本机没有 PostgreSQL 服务，未做真实执行。
- 同名物理表在多个接口里重复出现时，适配器按表名合并并写入 `importWarnings`；26 套案例里实际存在这种情况。

## 还没接上的部分

这一轮是内核层，不是发布版。以下仍然待做：

1. 现有生成器 `app/generator/sql.js` 还没切到 `dialects`；它仍生成 MySQL 全量 `DROP TABLE + CREATE TABLE`。内核迁移器是并行新增能力，尚未替换主生成链路。
2. UI 还没有“迁移计划 / 反向工程”入口；`projectFromRegistry` 只是桥，不写用户工程目录。
3. 字段改名识别还没做（表改名已按稳定实体 id 识别）；复合主键已支持，复合外键还没做。
4. PostgreSQL 反向工程 reader、真实 PostgreSQL 执行回归没做。
5. 真语言渲染器：Go/Rust 生成器已经存在且是原生代码，但完整导出里的 `launcher/Server.java`、`launcher/main.go` 仍以 Node `server.js` 为主入口；下一步是把启动器切到原生入口，或从完整导出中移除 Java/Go launcher。
6. 外键约束默认不生成（`registry.options.foreignKeys` 为真时才尝试），避免建表顺序和 SQLite 限制把初始化卡死。
