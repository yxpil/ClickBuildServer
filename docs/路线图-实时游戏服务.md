# ClickBuildServer 产品路线图（1.2 起）

这份路线图把“能跑的生成器”推进到“人能直接用的产品”。顺序不能倒：内核、方言、迁移、语言渲染器没做完，后面的实时能力都会建在沙滩上。

## 第一阶段：内核通用化

1. **独立元模型**：实体、字段、关联（一对多 / 多对多）、枚举、校验规则注册表，不再绑死“接口 = 表”。
2. **数据库方言层**：SQL 生成走方言接口，先 PostgreSQL、SQLite，再考虑 SQL Server / Oracle。
3. **表结构迁移**：版本化 migration，字段/索引变更自动生成 ALTER，能在已有数据的旧库上平滑升级。
4. **真语言渲染器**：Go 与 Java 先各出完整一套（实体 / 服务 / DAO / 路由 / 配置 / 测试），启动器与 Node 内核彻底退场。
5. **反向工程**：连接现有数据库读元数据，直接生成工程（MyBatis Generator 方向）。

## 第二阶段：通用业务积木

6. **认证插件化**：OAuth2 / SSO、短信 / 邮箱验证码、第三方登录，provider 可插拔。
7. **多租户隔离**：租户级数据、配置、套餐策略。
8. **存储适配器**：S3 之外接 OSS / COS / 七牛 / 本地磁盘；对象存储桶、Key、域名走界面配置，支持在生成器里直接创建桶和上传接口。
9. **通知通道**：邮件 / 短信 / Webhook，模板渲染 + 发送回执。
10. **消息队列**：Redis Stream 起步，再补 Kafka / RabbitMQ 适配器。
11. **权限扩展**：ABAC、字段级脱敏、组织级权限。
12. **搜索适配器**：Elasticsearch，替代现在只在 Redis 里做倒排的方案。
13. **可选纯 Redis 模式表**：表可标记为 Redis-only 或 Redis + MySQL 旁路；读走内存/ZSET/Hash，写按策略回刷，减少数据库读取；排行榜、在线状态、会话、验证码这类表直接不落 MySQL。
14. **表格导入**：工作台支持导入 Excel / CSV，自动识别表头并映射到字段，重复列可“替换位置”或追加，导入前给出差异预览。

## 第三阶段：部署与工程化

15. **跨端打包**：Linux / macOS 安装包；产物附 Docker Compose、K8s 模板。
16. **产物质量**：导出的工程自带单测 / 集成测试样板、lint、格式化、CI 配置。
17. **可观测**：指标、链路追踪、日志检索、告警规则。
18. **插件开放**：模板、渲染器、外部 DSL 可替换，不只是注入函数。
19. **协作**：版本 diff、历史快照、Git 联动、团队共享模板与接口库。
20. **前端适配层**：可选生成 Vue / React / 小程序，而不是只出 `.yxpp` HTML。

## 第四阶段：实时游戏服务

顺序固定：长连接网关 → 协议编解码 → 房间态模型 → tick 调度 → 状态/帧同步 → 断线重连。

### 1. 传输与连接层

- 长连接网关：WebSocket（网页 / 小程序）、TCP / KCP / QUIC（客户端）。
- 连接生命周期：握手鉴权（复用 onlyId + token）、连接注册、心跳、空闲踢除、断线检测。
- 断线重连：会话保持、重连换绑连接、离线期间消息补发。
- 连接映射：一个 onlyId 多端 / 多连接，踢下线策略。
- 网关横向扩展：连接落在哪台、消息怎么路由（一致性哈希 / 连接目录）。

### 2. 协议层

- 编解码：JSON 之外补 Protobuf / MessagePack / FlatBuffers，高频帧压体积。
- 消息路由：消息号 + 模块 + 动作，服务端按号分发 handler。
- 粘包拆包：TCP 长度前缀、半包缓存。
- 协议 DSL：工作台里声明消息结构，生成前后端类型与编解码，不手写。
- 压缩与校验：帧压缩、CRC / 签名防篡改。

### 3. 房间与实时同步

- 房间模型：创建 / 加入 / 离开 / 解散、成员列表、准备 / 开始 / 结束状态机、匹配队列。
- 房间态存储：热数据在内存，冷数据落库；不再只有 MySQL + Redis 旁路，补“内存态对象”一层。
- 同步方案：状态同步（定时快照 + 增量广播 + 服务端权威校验）；帧同步（输入指令广播、确定性回放、掉线追帧）。
- tick 调度器：固定步长（20Hz / 30Hz）、定时任务、延迟队列；现在的 `setup` 只有初始化钩子，没有运行时节拍器。
- 并发控制：同房间串行、房间级锁、乐观版本号。

### 4. 服务端主动推送

- WebSocket 双通道：房间频道、个人频道、全服公告。
- 复用 Redis PUBLISH 做跨实例总线，补“频道消息 → 对应连接”的出口。
- 离线消息、推送队列、未读计数。
- 广播 / 群发 / 点对点三种模式。

### 5. 游戏业务模块

- 复用：账号、onlyId 会话、RBAC、操作日志、限流、文件存储、审计。
- 新建：背包 / 道具 / 货币（强事务、防超扣）、装备强化、排行榜（Redis ZSET）、邮件 / 公告、任务成就、对战回放、聊天频道。
- 防作弊：关键操作服务端校验、输入合法性、速率限制、异常行为标记。
- 配置表：数值 / 掉落 / 关卡加载与热更新。

### 6. 可靠性与一致性

- 操作幂等：请求号去重，断线重发不重复扣费 / 发道具。
- 落库时机：状态先落内存、定时批量刷盘、关键事件（充值 / 结算）同步持久化。
- 宕机恢复：房间快照、崩溃后从快照重建、重连续传。
- 跨实例事务：跨服邮件 / 道具走队列补偿，覆盖消息最终一致。

### 7. 性能与部署

- 运行时：Node 事件循环适合 IO 业务，CPU 密集 tick 与广播会堵；实时网关与房间进程优先 Go / Rust。
- 水平扩展：房间粘性调度、跨服调用、服分组。
- 指标：在线数、房间数、连接抖动、帧延迟、队列积压、错误率。
- 压测：模拟大量连接 + 高频消息；现有 e2e 只有 HTTP 断言，没有长连接压测。
- 网关与业务分离：长连接网关无状态，房间进程按房间分片。

### 8. 生成器侧

- 新模块模板：长连接模块、房间模块、定时任务模块。
- 协议 / 消息定义编辑器（消息号、字段、方向）。
- 内存态存储抽象：内存 Map + Redis 备份 + 落库钩子。
- tick 调度器与延迟任务运行时。
- WebSocket / TCP 连接管理内核。
- 游戏案例模板：房间对战、聊天房间、排行榜、匹配。
- 产物区分“业务后台服务”和“实时游戏服务”两种运行形态。

## 当前落点

- Go 原生：已读取 `service.json` 直接运行，路由 / 脚本 / SQL / MySQL / TOKEN / SM4 / 事务 / 上传可用，不再启动 Node。
- Java 原生：同一份 `service.json`，JDK 编译 `native/java/src/icb`，JDBC + Gson + BouncyCastle，已通过登录、`/me`、列表、事务回滚回归。
- 两者尚未接 Redis 缓存 / PUBLISH、S3、外部 HTTP；缺失能力明确报错。
- 实时游戏服务只完成本文件与模板规划，代码从第四阶段第 1 步开始。
